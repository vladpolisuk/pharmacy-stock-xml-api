# Остатки на складе лекарств — XML API

Лабораторная работа, вариант 21: **Fedora + Nginx + MariaDB**, формат ответа — **XML**. API читает остатки из базы данных. Веб-интерфейс позволяет задать фильтры и проверить сформированный GET-запрос, HTTP-статус, заголовки и исходный XML-ответ. Таблица строится из этого же ответа.

## Запросы

| Метод и путь | Результат |
|---|---|
| `GET /` | Страница с таблицей остатков |
| `GET /api/stock` | Остатки из MariaDB в формате XML |
| `GET /api/stock?download=1` | Скачивание файла `medicine-stock.xml` |
| `HEAD /api/stock` | Заголовки ответа без тела |

API возвращает `Content-Type: application/xml; charset=UTF-8`. Некорректные параметры получают HTTP 400 и XML с кодом `invalid_parameter`. Другие методы получают HTTP 405. Если база недоступна, возвращается HTTP 503.

## Демонстрация в браузере

При настроенном NAT откройте на Windows `http://127.0.0.1:8082/`. В Fedora используется `http://127.0.0.1/`.

1. Выберите готовый пример или заполните поля и нажмите **Выполнить GET**.
2. В первом блоке проверьте сформированный адрес с URI-параметрами.
3. Во втором блоке проверьте HTTP-статус и число записей. Заголовки доступны в раскрывающемся блоке.
4. Переключайте вкладки **XML** и **View**: исходный XML с подсветкой и таблица представляют один полученный ответ. Переключение вкладок не отправляет новый запрос.

Кнопки примеров: **Все записи**, **ID 1**, **ID 2**, **Два фильтра**, **Нет совпадений**, **Ошибка 400**, **Экспорт XML**. При изменении полей адрес обновляется сразу и появляется предупреждение о необходимости обновить ответ. Данные меняются после выполнения нового запроса.

Для просмотра заголовка `Content-Disposition` выберите **Экспорт XML** или включите **download=1**, затем раскройте **Заголовки ответа**. Ссылка **Скачать XML** сохраняет файл с учётом текущих фильтров.

## URI-параметры API

Параметры передаются в строке запроса после `?`. Несколько параметров соединяются через `&`; условия применяются одновременно.

| Параметр | Фильтр |
|---|---|
| `balance_id=1` | Остаток с указанным идентификатором |
| `drug_name=препарат` | Название содержит заданный текст без учёта регистра |
| `batch_number=00021-A` | Точное совпадение номера партии |
| `storage_temperature=+2…+8 °C` | Точное совпадение температуры хранения |
| `min_quantity=1` | Количество не меньше указанного, включая границу |
| `max_quantity=100` | Количество не больше указанного, включая границу |
| `expiry_after=2027-01-01` | Срок годности не раньше даты, включая границу |
| `expiry_before=2027-12-31` | Срок годности не позже даты, включая границу |
| `download=1` | Скачать результат с теми же фильтрами |

Примеры:

```text
/api/stock?balance_id=1
/api/stock?min_quantity=1&expiry_before=2027-12-31
/api/stock?batch_number=00021-A&download=1
```

Кириллицу и специальные символы кодируйте средствами браузера или `curl --get --data-urlencode`:

```bash
curl --get --data-urlencode 'drug_name=препарат' 'http://localhost/api/stock'
curl --get --data-urlencode 'storage_temperature=+2…+8 °C' 'http://localhost/api/stock'
```

Без фильтров возвращаются все записи; при отсутствии совпадений — HTTP 200 и пустой `<stock_balances/>`. Идентификатор — целое число от 1, количество — от 0; верхняя граница — 4294967295. Даты задаются в формате `YYYY-MM-DD`. Пустое значение фильтра пропускается. Неизвестные параметры, массивы, ошибочные даты и перевёрнутые диапазоны отклоняются с HTTP 400.

Значения передаются в SQL через PDO `prepare` и `bindValue`, с отключённой эмуляцией подготовленных запросов. Символы `%` и `_` в поиске по названию обозначают буквальные символы.

## Поля

| Поле XML и БД | Значение |
|---|---|
| `balance_id` | Идентификатор остатка |
| `drug_name` | Название препарата |
| `batch_number` | Номер партии |
| `expiry_date` | Срок годности |
| `quantity` | Количество единиц |
| `storage_temperature` | Температура хранения |

Номера партий хранятся как текст, чтобы сохранять ведущие нули. Температура задаётся текстовым диапазоном. В базе три вымышленные учебные записи; пример ответа находится в [example.xml](example.xml).

## Файлы проекта

- `public/api.php` — обработчик API.
- `src/stock.php` — чтение MariaDB через PDO и формирование XML через DOMDocument.
- `public/index.html`, `public/app.js`, `public/style.css` — простой интерфейс, который получает данные из API.
- `database/schema.sql` — база, таблица, учебные записи и пользователь с правом SELECT.
- `config/` — учебные настройки подключения, Nginx, PHP-FPM и MariaDB.
- `scripts/apply.sh` — обновление API и интерфейса работающего стенда с резервной копией.
- `tests/test_api.py` — HTTP-проверки фильтров и ошибок на трёх исходных учебных записях.
- [GUIDE_RU.md](GUIDE_RU.md) — инструкция от установки Fedora VM до проверки API с Windows.

## Развёртывание

Требуются Nginx, MariaDB и PHP-FPM с расширениями PDO MySQL и DOM/XML. Веб-корень — `/var/www/pharmacy/public`, конфигурация подключения — `/etc/pharmacy-lab/config.php`. Другой путь к конфигурации можно задать переменной окружения `PHARMACY_CONFIG`.

Для получения файлов на Fedora установите Git и клонируйте репозиторий в каталог, который используется в инструкции:

```bash
sudo dnf install -y git
git clone https://github.com/vladpolisuk/pharmacy-stock-xml-api.git "$HOME/pharmacy-lab"
```

На время передачи репозиторий публичный: для клонирования авторизация GitHub не требуется. После получения файлов репозиторий можно удалить с GitHub; локальная копия и приложение в Fedora сохранятся.

Получение и обновление файлов через Git описаны в разделе 7 [инструкции](GUIDE_RU.md), настройка приложения — в разделах 8–13. Если серверные пакеты и сеть ещё не настроены, начните с раздела 5.

Пароль в `config/config.php`, SQL и инструкции — общий учебный пример. Для другого стенда задайте собственный пароль пользователя БД и укажите его в `/etc/pharmacy-lab/config.php`. Рабочие настройки и пароли храните вне репозитория.

Для обновления уже настроенного стенда:

```bash
git -C "$HOME/pharmacy-lab" pull --ff-only
sudo bash "$HOME/pharmacy-lab/scripts/apply.sh"
```

Скрипт проверяет PHP и текущие конфигурации, сохраняет прежние каталоги `public` и `src` в `/var/backups/pharmacy-lab/`, устанавливает новую версию, восстанавливает SELinux-контексты и перезагружает PHP-FPM. Текущие настройки подключения, Nginx и данные MariaDB сохраняются. При ошибке установки файлы приложения восстанавливаются автоматически.

## Проверка

После настройки сервера внутри Fedora:

```bash
curl -i http://localhost/api/stock
curl -o medicine-stock.xml 'http://localhost/api/stock?download=1'
curl -i -X POST http://localhost/api/stock
python3 "$HOME/pharmacy-lab/tests/test_api.py"
```

Ожидаются XML с тремя записями, скачиваемый XML и HTTP 405 для POST. Для проверки с Windows откройте `http://IP-Fedora/` и `http://IP-Fedora/api/stock`.
